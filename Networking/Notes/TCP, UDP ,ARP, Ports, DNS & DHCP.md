TCP Vs UDP:
- works at transport layer

TCP( transmission control protocol):
- slower
- whicle sending the datat from 1 host to the other, it is sent in small packets, and once it reaches its dest. it will be put together and given out as a single complete file
- But what happens when some of these packets are lost? the destination host wouldnt be able to recognize it and would put together all the data it got to create a complete file, but this would result in a corrupted file
- TCP resolves this
- wildely used option for transmitting data
- This is bcz it can reliably send and recieve data
- which means, in the process of sending data, if any of the data is lost, TCP will help recover that data
- this will increase UX bcz this will prevent the resultant corrupted file and websites
-uses too much resource
-more latency
-used for web browsing, file transfers etc

3 way handshake:
-done by using acknowledgements, sequencing, checksum
- Inorder to make the connection reliable between the devices, TCP used 3 way handshake
- First host A would send an SYN to host B
- when Host b recieves it, it will answer to it with a SYN-ACK to host A
- Once Host A recieves this SYN-ACK packet, it will reply with an ACK bit and thus the connection is secured.
- this similar process is carried out while closing the connection too
- Sequence numbers: TCP will assign sequence No's to the data as its sent, so that in the destination, it will reordered properly and put together
- Checksum: is a result of a simple calculation run against the data
- Once the data is transmitted successfully, the checksum generated by the sender must match the chechsum generated by the reciever. If there is a mismatch at the reciever side, the segment will be discarded

UDP ( User Datagram Protocol):
- unreliable communication
- it dosnt have sequencing, reliability  or error handling of TCP
- its faster
- It just broadcasts data irrespective of if the data has been delivered at the destination or not
- uses less resources
- less latency
- used for voice calls, video calls, gamings

80,443- webpages( HTTP, HTTPS)

Port numbers are broken into 3 categories:
i. 0-1023( System/well-known ports=> 80(http),443(https),25(smtp),21(ftp)
ii. 1024-49151( User/ registered ports) => these r registered by companies and developers for a particular service=> ( 1102-Adobe Server, 1433-Microsoft SQL server, 1416-novell, 1527-Oracle)
iii. 49152-65535(Dynamic/private ports)=> these r client side ports that r free to use and these are assigned temporarily by the computer to itself during the session=> eg: when viewing a web page
- categories 1 and 2 are used on server and category 3 is used on the client machine

ARP( Address resolution Protocol):
-discover mac address and map then to IP address
- If there r 4 computers in a network connected by a swicth( so switch is a layer 2 device and needs mac address)
- The host A has to send a message to Host D, but it only knows Host D's IP address
- So Host A will send out a broadcast message asking who among u all has IP of 10.0.0.4
- So since host B and Host C are not of that IP address, they just discard it
- As its the IP address of Host D, it will reply it with its MAC address to host A.
- This mapping of IP address and MAC address is then saved in the ARP cache, so in the future if there is any kind of communication between these 2 devices, it can happen directly using the cache

- ARP requests only happen in layer 2 networks
- So when u have the dest as 10.10.10.10 and Host A has IP of 192.168.0.1, Host A understands that the dest. host is not in the same network
-So now as it knows it has to go out of its network, it will send the ARP request to its default gateway(router) instead of the web server
- the router will respond with its mac address
- Now host A will send the data with mac address of the router and the IP address of the web server.
- Once the data reaches the router, the router will handle things from here to the web server

DNS ( domain Name system)
- resolves domain names to IP addresses
- Initailly, when u give a browser name like yahoo.com,the system initailly ties to search for its IP address in its cache,  if its not found, it will then send it to a resolver(the next level)
- The resolver server is basically ISP, so it will check its cache, if not found it will send it to the root server
- The root server is the top lever of a DNS heirarchy
- there are 13 sets of these root servers stratergically placed around the world
- Operated by 12 different organizations and each set has its own unique IP address
- When the IP is sent to the Root server, it wouldnt know where to find that IP, so the root server will send a TLD(Top level domain) server for the .com domain to the resolver
- The resolver will now send this to the TLD server and ask the IP address for Yahoo.com
- TLD stores address info abt the top level domain, Eg: .com, .net,.org etc
- But now the TLD server will not know the IP addresses, so it will direct the resolver to the next level, i.e Authoritative name server
- Authoritative name server r responsible for knowing everything about the domain including the IP address
- Now the Authoritative name server will now have the IP address and this is sent to the resolver, which then ends it to ur device as the IP address of Yahoo.com
- The resolver will store this IP in its Cache, so that next time it receives a query regarding Yahoo.com, it would have to do this entire step again
- This is called the DNS lookup

DHCP:( Dynamic host configuration protocol)
- main role: assign unique IP addresses to the hosts
- also provides other network addresses like, default gateway, DNS and subnet mask
- comes as client and a server
  
Working:
- Every computer needs a unique IP address
- every computer will run a DHCP client, this is connected to the DHCP server present on the server(can be a router/server based on business usecase)
- Step 1: DHCPDiscover: The DHCP client will send a broadcast message asking for an IP address to the server, since this is a broadcast message, it would be sent to all the devices and servers connected to that network, If its not the intended host, that request it just discarded
- Step 2: DHCPOffer: Now the server will receive this request and broadcast a reply with an IP address over the network. if >1 IPs are sent, the host will accept only the first one it recieves
- Step 3 : DHCPRequest : Once the server send the IP and the Host A recieves it, it will send a reply back to the server saying something like..I recieved it!
- Step 4 : DHCPACK : the server will reply to the Host A's message with a subnet mask, default gateway and DNS server( something like..ok..u can take this IP, but I want it back)
- the server keeps track of the IP addresses, mac and the expiration time ( least time -> the time within which it must renew that address, or else it would be revoked by the server and made available for other hosts for use)
- this prevents IP addresses from wasting out when u either discard ur computer/ unplug it
